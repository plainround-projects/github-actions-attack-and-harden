# Prettier

## What it is

Prettier is a **code formatter**. It reads a source file, throws away how the original author laid out the text (spaces, line breaks, quote marks), and prints the same code again in one fixed style. Nothing about what the code *does* changes. Because every file ends up in the same style, nobody argues about layout and diffs show real changes only.

Prettier handles many file types. In this repository it formats TypeScript, JavaScript, JSON and YAML. It is separate from ESLint: ESLint looks for mistakes and rule breaks, Prettier only decides where spaces and line breaks go.

## Why this repository uses it

A formatter makes the style a machine's job. CI runs `prettier --check`, which fails when any file is not already formatted, so unformatted code cannot be merged, and `make format` fixes everything in one command.

## Where it appears

| Path | What it does |
| --- | --- |
| `.prettierrc.json` | The four options. |
| `.prettierignore` | Files Prettier must leave alone. |
| `package.json` | `"lint"` runs `prettier --check .`; `"format"` runs `prettier --write .`. |
| `Makefile` | `make lint` runs `npx prettier --check .`; `make format` runs `npx prettier --write .`. |
| `.github/workflows/ci.yml` | Job `app` runs `npm run lint`, which includes the check. |

## How it works underneath

1. Prettier parses the file into a syntax tree (it knows the grammar of each language).
2. It throws away all original whitespace information, except that it keeps blank lines between statements (at most one) and a few other hints.
3. It prints the tree from scratch with its own algorithm: put as much on one line as fits within `printWidth`; when something does not fit, break it at the outermost possible place and indent the pieces.
4. `--check` compares the result with the original and reports files that differ (exit code 1). `--write` overwrites them.

Because the output depends only on the tree and the options, two very differently formatted inputs with the same meaning produce identical output.

## Walkthrough of this repository's use

```json
{ "printWidth": 120, "tabWidth": 2, "singleQuote": false, "trailingComma": "all" }
```

- `printWidth: 120`: lines can be up to 120 characters before Prettier wraps them (the default is 80). Long GitHub expressions and policy lines would otherwise wrap awkwardly.
- `tabWidth: 2`: indent by two spaces. This matches `.editorconfig` (`indent_size = 2`).
- `singleQuote: false`: use double quotes for strings.
- `trailingComma: "all"`: put a comma after the last item of any multi-line list, object or function call. That makes adding an item a one-line change.

```text
dist/
build/
coverage/
node_modules/
package-lock.json
exploit/
infra/
*.tfvars
*.md
```

(`.prettierignore`, the same syntax as `.gitignore`.) Compiled output, generated files and dependencies are skipped. `package-lock.json` is generated by npm. `exploit/` holds deliberately odd lab files (including line-number-sensitive ones that the review checklist points to). `infra/` is Terraform, which has its own formatter (`terraform fmt`, see `terraform.md`). Markdown is skipped so the documents keep their hand-written tables.

You can see the effect in the source. In `pipeline/harden-lint.ts` the call that reports `broad-permissions` is spread over several lines, one argument per line with a trailing comma, because it did not fit in 120 columns. Short calls stay on one line.

## Try it yourself

1. `npx prettier --version` prints `3.9.10`.
2. `npx prettier --check .` prints `All matched files use Prettier code style!`.
3. `echo 'const x = {"a":1,b:   2}' > /tmp/p.ts && npx prettier --config .prettierrc.json /tmp/p.ts` prints `const x = { a: 1, b: 2 };`.
4. `npx prettier --check /tmp/p.ts; echo $?` reports a warning for the file and prints `1`.
5. `npx prettier --find-config-path src/main.ts` prints the path of `.prettierrc.json`.

## Mistakes people make

- Formatting by hand and fighting the tool.
- Running Prettier and ESLint with conflicting layout rules. (This repository gives ESLint no layout rules.)
- Reformatting generated files such as lock files.
- Committing unformatted code and letting CI find it; run `make format` first.

## Check yourself

1. Does Prettier change what code does? *(No, only layout.)*
2. What is the difference between `--check` and `--write`? *(`--check` only reports; `--write` rewrites the files.)*
3. Why `trailingComma: "all"`? *(A new last item changes one line instead of two.)*
4. Why is `package-lock.json` ignored? *(It is generated by npm and must keep npm's layout.)*
5. Why is `infra/` ignored? *(Terraform has its own formatter.)*
